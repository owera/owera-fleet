# markers

**Trigger:** `/markers`

## Summary

Record and verify content-hashed step markers for idempotent pipelines (ETL-style step skip).

## Arguments

| Flag | Meaning |
|---|---|
| `hash` | Hash --input and write a marker for --pipeline/--step. |
| `verify` | Check the marker for --pipeline/--step against --input; exit 0 fresh, 1 stale/missing. |
| `list` | List markers, optionally filtered by --pipeline. Use --format=json for machine output. |
| `invalidate` | Remove the marker for --pipeline/--step (idempotent). |
| `--pipeline NAME` | Pipeline identifier (required for hash/verify/invalidate; optional filter for list). |
| `--step NAME` | Step identifier within the pipeline (required for hash/verify/invalidate). |
| `--input PATH` | Input file to hash, or '-' for stdin (required for hash/verify). |
| `--output PATH` | Optional output path recorded on the marker (hash only). |
| `--format FMT` | List output format: table (default) or json. |
| `--markers-dir PATH` | Override the marker storage root (default: ~/.hermes/markers). |

## Examples

**Record a marker after a step succeeds:**

```
fleetctl markers hash --pipeline etl --step load_users --input data.csv
```

**Skip a step if its input is unchanged:**

```
fleetctl markers verify --pipeline etl --step load_users --input data.csv
```

**List markers as JSON for a pipeline:**

```
fleetctl markers list --pipeline etl --format json
```

**Force a step to re-run on the next pass:**

```
fleetctl markers invalidate --pipeline etl --step load_users
```
